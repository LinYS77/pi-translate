# 手工验收：真实模型与 pi 终端

自动化测试不调用真实模型。这份清单用于验证你实际选择的翻译 provider、终端和主模型。

## 准备

1. 确认 `pi --version` 至少为 0.99.2。
2. `pi -e ./src/index.ts`，或安装本地目录后启动 pi。
3. `/translate` 打开设置，选择“翻译模型”，搜索并选择一个已配置凭据的小模型。
4. `/translate off`。记住当前主模型，过程中确认它不会被翻译扩展更换。
5. 如需检查会话 JSONL，请用独立的测试会话，避免分享真实凭据和项目隐私。

## 设置与状态栏

- `/translate` 打开设置，不直接切换开关。Alt+T 或 `/translate toggle` 只切换开关，无弹窗。
- 在 `/translate` 菜单选择“翻译模型”，搜索模型名称、ID 和 provider；同名模型的 provider 必须区分清楚，当前模型带 `✓`。
- Esc 取消不保存、不切换主模型；在活动任务中取消设置，也不应取消该任务的最终翻译。
- 在菜单中改变“新对话默认”：保存后当前开关保持原样，新对话按该值初始化。
- 临时关闭后换模型，再新建对话，默认开关仍应保持原先保存值，不能被临时开关覆盖。
- 页脚显示 `译 on` / `译 off`；翻译时只追加一个动态 spinner（如 `⠹`），不显示方向文字，完成/失败/取消后停止。只有当前任务快照不同、缺少模型或配置错误时显示其他补充文字。
- 切换会话、`/reload` 或退出时不应残留动画，也不能用旧定时器更新新会话。

## 输入与忠实性

先关闭功能提交一句中文，确认没有翻译调用或额外译文。

按 Alt+T，状态栏应显示 `译 on`，不出现确认弹窗。逐次提交以下内容，并核对会话中交给主模型的英文 user message：

| 输入 | 必须保留的含义 |
| --- | --- |
| 先检查原因，不要修改文件，也不要重新运行训练。 | 先检查；不得改文件；不得重跑训练 |
| 按刚才第二种方案修改，但先不要运行训练。 | 保留历史指代，不自行展开第二方案；先不训练 |
| 把按钮文字改成“保存”，不要改变量名。 | 目标字面字符串仍是“保存”，不是 Save |
| 只解释 gradient accumulation 和 `batch_size`，不要改配置，值保持 0.25。 | 原有英文、标识符、数值不变；只解释，不改配置 |
| Do NOT modify files. Inspect first, then report uncertainty. | 英文原文逐字保留，不润色，不调用输入翻译 |

在用户输入中附加图片：图片应直接交给主模型，不发给翻译模型。把代码/命令放在反引号或代码块中，核对代码逐字一致。

## 最终回答边界

在临时测试项目中让主模型检查一个文件并给出报告（无需执行危险操作）：

- “我会先检查文件”等进度文字仍原样出现，不产生中文翻译卡片。
- 工具名称、参数、结果、日志和可见思考不被翻译。
- 最终回答完成、整个任务 settled 后，原文下方直接出现中文正文，没有额外标题或标签。
- 普通段落、标题、列表、表格和代码块的视觉样式、横向 padding、代码缩进以及消息间距，应与 pi 原生 assistant 输出一致，不能多一层留白。
- 表格、列表、标题、代码块保留；结论、否定、数量、警告和不确定性没有变成摘要。
- 原回答已经是中文时，不应重复产生改写版中文卡片。
- 在有工具调用的执行中按 Esc：不把进度或前一轮答案当成这轮最终回答。

## 开关与排队

1. 开启时提交 A；执行期间关闭。A 仍应按开始时快照翻译最终回答，状态栏显示 `译 off · 本任务 on`。
2. 关闭时提交 B；执行期间开启。B 不追溯翻译。
3. 在任务中分别使用 Enter steering 和 Alt+Enter follow-up。输入各自按提交时状态翻译，最终输出按这个 pi 活动最初的快照；没有重复提交、没有提前翻译中间结论。
4. 输入翻译期间再次提交：后一次内容保留为未提交记录，不越过前一次执行。
5. 切换翻译模型不会修改主模型；执行中的任务仍使用原先的翻译模型快照。

## 上下文隔离

完成一轮并继续下一轮，检查测试会话的 JSONL：

- 只有一个经过转换的 user message 交给主模型，不存在中文原文与英文译文两个 user 请求。
- assistant 的原回答未被替换。
- 中文译文位于 `type: "custom"`、`customType: "pi-translate.output"` 的 entry，不是 `custom_message` 或 user message。
- 用 SDK 的 `sessionManager.buildSessionContext().messages` 检查，中文译文不在上下文中。
- 若 provider 有调试请求日志，翻译请求只能有翻译规则和这一份文本（字面部分是占位符）；没有历史、主系统提示、项目文件或工具结果。

## 失败与恢复

1. 将配置中的 provider/model 临时改为不存在的值，`/translate reload` 后提交中文。
2. 应明确失败且不运行主任务。原文保留，可 `/translate recover` 恢复；已有草稿不得被覆盖。
3. 将 `timeoutMs` 临时设为 `100`，或断开测试 provider 的网络，验证超时同样阻止输入、保留原文。
4. 在主任务进行时让翻译 provider 不可用：最终输出翻译失败，但主任务不会重跑，原回答仍可阅读。
5. 输入/输出翻译过程中按 Esc、切换会话或退出：没有迟到的译文出现在新会话。输入请求前的原文备份留在原会话。
6. 恢复正常配置。失败输入只能由用户主动重交，扩展不自动重放。

## 阅读体验

在常用终端的正常模式与 fullscreen 模式验证：

- 长中文回答可在对话区域正常滚动、选择，不在通知或页脚中展示。
- 将宽度调整到 40/80 列，检查标题、表格、中文和代码块。
- 切换 pi 主题并重绘，颜色和排版跟随原生组件。
- 切换开关只更新状态栏，不反复弹窗。
- `/reload` 或重开已有会话只重绘保存的 custom entry，不触发历史翻译；旧译文也应使用无标题的原生排版。
