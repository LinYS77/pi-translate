# v0.2.0 validation

This records observed checks, not a claim that semantic translation fidelity can be proved.

## Automated and packaging checks

- `npm run verify`: **108 tests passed**, strict TypeScript, formatting, actual npm tarball loaded through Pi's resource loader.
- The same suite passed on all four combinations: Pi **0.99.2 / 1.0.0**, Node **22.19.0 / 24.9.0**. CI now keeps this host/version matrix.
- Package: **15 files**, about **30.4 KiB** packed. New runtime modules are included; tests, evaluation scripts and maintainer documents are excluded.
- Tests cover precise timeout editing, route/model independence, configuration persistence, active-task snapshots, partial-output warnings, input all-or-nothing, bounded repairs, shared deadlines, cancellation/late replies, invalid classifier responses, classifier batching/fallback, source-range assembly and context isolation.
- The default suite uses fake providers and temporary settings; it makes no paid model calls and does not read user credentials.

## Real-model evaluation

Command used the opt-in script, the public synthetic fixtures and a temporary copy of the v0.1.1 translator obtained with `git show`. No conversation history was read or sent.

```bash
git show v0.1.1:src/translator.ts > /tmp/pi-translate-baseline-v011.ts
PI_TRANSLATE_EVAL_BASELINE=/tmp/pi-translate-baseline-v011.ts \
PI_TRANSLATE_EVAL_PROVIDER=deepseek PI_TRANSLATE_EVAL_MODEL=deepseek-flash \
  npx tsx scripts/evaluate-routing.ts --live --translate
```

### Translation judgment

Classifier: **typesafe/jev-latest**, through Pi's real `ModelRegistry.classify()`.

| Route | Passage-level judgment mismatches / 16 fixtures |
| --- | --- |
| v0.1.1 local baseline | 3 |
| v0.2.0 local | 0 |
| v0.2.0 Jev | 0 |

The old route unnecessarily translated the Docker/PyTorch and `gradient accumulation` examples, and missed plain `STOP`. Both new routes matched the fixture expectations. Deterministic passthroughs made no classifier call; 11 remaining examples made 11 requests (13 candidate questions). No fallback was needed in this run. Nonzero classifier latencies ranged from roughly **356–938 ms**; most were around **370–400 ms**.

These are **16 selected, development-time fixtures**, not an independent benchmark or an estimate of real-world accuracy. The table measures whether a passage needs translation, not every translated token. The initial gates (chosen option probability ≥ 0.8, confidence ≥ 0.5) accepted these examples; confidence is not calibrated correctness. TypeSafe's documented lower CJK accuracy and `latest` model drift remain risks. Local stays the default.

### Bidirectional smoke translation

Translation model: **deepseek/deepseek-flash**, with the Jev route enabled.

- Input: ``先检查原因，不要修改 `src/main.ts`，也不要重新运行训练。``
  - Result: ``First investigate the cause. Do not modify `src/main.ts`, and do not rerun training.``
  - Path, investigation-first instruction, both prohibitions preserved. About **1.38 seconds** including classification.
- Output: an English completion paragraph, a TypeScript fence containing `const label = '保存';`, and `Warning: do not retry after 42 seconds.`
  - Result retained the code fence byte-for-byte, translated the prose and warning, and preserved `42`. About **1.57 seconds** including classification and two translation requests.
- Both operations completed without repair or partial degradation. Failure/degradation frequency cannot be estimated from two smoke operations; those paths were fault-injected in automated tests.
- Pi reported 927 / 1465 total tokens for the input/output operations, combining completed classifier and translation responses. Direct TypeSafe pricing was absent in Pi's catalog, so displayed cost is **not a complete provider bill**.

Timing includes transient provider/cache behavior; these single runs do not establish speed rankings or failure rates.

## Deliberate implementation choices

- A small source-position scanner, not Markdown parse-and-reserialize. Common structures retain exact source bytes; unusual Markdown/HTML and deeply nested indentation remain limitations.
- Sequential, one-fragment translation requests avoid ambiguous batch-output ID reconstruction. Classifier requests batch up to eight independent questions.
- Long paragraphs split at available sentence/whitespace boundaries around 1600 UTF-16 code units, outside recognized inline opaque ranges. Oversized indivisible fragments are rejected rather than truncated.
- Internal caps: 8-second classifier wait, 12,000 bytes of classifier candidate text per batch, 64 total requests, 131,072 conservatively reserved tokens per operation. Reservation counts input bytes plus maximum output allowances, including repair overhead; long documents can hit this earlier than actual provider usage would suggest.
- One local integrity-repair attempt, with explicit repair instructions. No retry on provider error/abort/length. No guessed insertion of missing literal content.
- Output deadline exhaustion can keep completed fragments, but explicit cancellation discards pending output. Input never submits partial results.
- `src/request-budget.ts` was added beyond the initial file sketch to centralize the real shared deadline, cancellation, token reservation and usage responsibilities for both routes.
