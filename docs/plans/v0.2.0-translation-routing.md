# v0.2.0 实施计划：超时设置与双路线翻译判断

- **状态**：实现、回归和发布准备已完成；23 项实施检查项已验收。npm 正式发布仍由维护者单独执行。
- **验收证据**：[v0.2.0 validation](../releases/v0.2.0-validation.md)；包括 108 个测试、四组 Pi/Node 组合、八组真实 TUI 组合、16 个真实 Jev 判断样例和基线/双路线翻译对比。
- **基线**：v0.1.1；当前行为见 [behavior.md](../behavior.md)。
- **目标版本**：v0.2.0。
- **范围**：在 `/translate` 配置超时；改进本地判断与内容保留；加入可选 Jev 判断路线。

## 1. 核心问题与已确认决策

这次需要解决两个不同的问题：**哪些内容值得翻译**，以及**怎样让模型只修改这些内容**。Jev 负责前者，不替代翻译模型，也不能保证后者。

现有流程把大量中文、英文术语、数字与代码替换为长占位符，整篇交给翻译模型复制；某个占位符遗漏就拒绝整篇。它降低了误改字面内容的风险，但让长文和混合语言文本容易失败。改进方向是减少模型需要复制的内容、缩小失败范围，而不是直接删除校验。

以下策略已确认：

1. **两个判断路线，共用一个翻译流程**：本地规则为默认，Jev 为用户主动选择的增强路线。
2. **输入必须完整成功才提交**：任何需要翻译的片段最终失败，都阻止整个输入提交，保留原文；不得提交部分译文或偷偷提交原始中文。
3. **输出允许局部降级**：失败片段保留原文，成功片段正常显示，并明确提示“部分段落保留原文”。原 assistant 回答始终保留。
4. **Jev 失败或不确定时可见回退**：明确提示后，对受影响内容使用本地规则，不逐段弹窗。用户取消不是回退条件，应直接停止。
5. **超时、路线和模型均遵循快照**：设置变更影响后续操作，不修改正在执行的输入翻译或当前任务的输出策略。

## 2. 不变约束与非目标

- 只有 `/translate` 命令，无子命令，不接入 Pi `/settings`；Alt+T 的语义不变。
- 仅处理当前交互输入、任务真正 settled 后的最终回答；不翻译过程文字、工具、思考、历史回答。
- 不切换主模型，不重复提交，不自动重跑主任务，不因设置界面中的 Esc 取消主任务。
- Jev 与翻译模型只能接收固定规则和当前文本中的必要内容；不得读取历史、主系统提示、工具结果、项目文件或附件作为额外上下文。
- 所有译文、警告和诊断仍通过非上下文 custom entry 或 UI 表达，不伪造成模型消息。
- 不解析“上面的第二种方案”等历史指代，不扩写、总结或润色输入。
- 不做通用多语言识别平台、文件翻译、模型自动切换、术语词典管理界面或独立 HTTP/凭据系统。
- 不承诺语义级零误判、零漏译；程序校验无法证明普通正文翻译的准确性。

## 3. 目标流程与职责

```text
当前输入 / settled 最终回答
        ↓
结构识别：保留原文位置，区分正文与不可变内容
        ↓
候选句段
        ↓
本地规则 或 Jev 分类
        ↓
翻译计划：保留 / 翻译 / 不确定
        ↓
共享翻译执行：分批调用、局部校验、有限恢复
        ↓
按原文位置组装
        ↓
输入：完整成功才提交
输出：完整或明确标注的局部降级显示
```

### 文件分工

| 文件 | 计划职责 |
| --- | --- |
| `src/config.ts` | 新字段验证、默认值、旧配置兼容、原子保存 |
| `src/settings-pane.ts` | 超时、判断路线和分类模型设置，保持单 overlay |
| `src/model-picker.ts` | 复用搜索交互；区分 chat 翻译模型与 classifier 判断模型 |
| `src/translation-plan.ts`（新增） | 当前文本的原文区间、候选句段、本地判定、翻译计划与原位组装 |
| `src/jev-classifier.ts`（新增） | 通过 Pi 分类接口产生句段决策，处理批次、答案校验和不确定性 |
| `src/translator.ts` | 共享翻译调用、总期限、局部保护、恢复、结果与用量汇总 |
| `src/extension.ts` | 保留生命周期编排；传入完整快照，按输入/输出政策处理结果 |
| `src/index.ts` / `src/output-view.ts` | 保持原生译文排版，仅补充必要的降级提示 |

不新增通用插件框架或多层工厂。候选区间与决策是内部数据契约；Pi 的模型接口已有真实生产实现，测试以模拟 provider 替代网络。

### 内部数据约束

- 原文区间有稳定 ID 与明确偏移单位；建议统一使用 JavaScript UTF-16 字符串偏移，切分不得截断代理对或组合字符。
- 区间按原文排序、无重叠；组装只替换已确定的范围，不对整篇 Markdown 重新格式化。
- 判断模块返回固定 ID 对应的 `translate`、`keep` 或 `uncertain`，不能自行生成文本、偏移或扩大范围。
- 翻译结果应区分 `unchanged`、`complete`、`partial`，携带必要的 warnings、失败片段 ID 和累计 usage；具体 TypeScript 形状在实现时确定。
- 取消通过明确的原因传播，不得被误当成分类故障、低置信度或输出局部失败。
- 历史 custom entry 可继续渲染；新增字段可选，不重算历史译文。

## 4. `/translate` 与配置

### 菜单

| 项目 | 行为 |
| --- | --- |
| 翻译模型 | 保持现有 chat 模型选择 |
| 判断方式 | 本地规则 / Jev，默认本地规则 |
| 判断模型 | Jev 路线下显示；使用 classifier 模型目录，独立保存 provider/model |
| 翻译超时 | 1、5、10、20、30、60 分钟预设及自定义；显示分钟/秒 |
| 当前开关 | 临时切换，不写入新会话默认值 |
| 新对话默认 | 保存默认状态，不改变当前开关 |
| 恢复输入 | 有可恢复记录时显示，保持现有手动重交行为 |

- 保留一个 overlay，在内部切换子视图；增加菜单项后需要滚动，不能截掉当前选中行或退出提示。
- 自定义超时沿用 `100–3600000` 毫秒的有效范围；界面可以用秒输入，但转换必须精确，不能悄悄舍入已有值。
- 保存成功才提交配置；失败恢复旧值并在面板内提示。重复 Enter、关闭后重开与异步写入竞态仍受保护。
- 模型目录刷新不发起付费测试请求；设置未完成时不得悄悄将一个普通 chat 模型当成 Jev。

### 配置方案

保留已有字段，新增以下字段；以严格解析和向后兼容为准：

```json
{
  "enabled": false,
  "provider": "deepseek",
  "model": "deepseek-flash",
  "timeoutMs": 600000,
  "maxTokens": 8192,
  "decisionMode": "local",
  "classifierProvider": "typesafe",
  "classifierModel": "jev-latest"
}
```

示例不表示绑定这些 provider。用户可通过 Pi 已配置的可用分类模型选择实际接入点。

- 缺少 `decisionMode` 的旧配置按 `local` 加载；保持显式超时、翻译模型和开关不变，不在读取时自动重写文件。
- classifier provider/model 要么同时缺省，要么同时提供；切回本地模式仍保留已选分类模型，便于再次切换。
- Jev 路线未配置或运行时不可用时，给出可见提示并回退本地；设置面板明确显示未配置状态。
- 所有新增设置独立于临时 Alt+T 开关保存。
- 暂不向菜单暴露置信度、批次大小、并发等调优参数，避免把工程细节交给用户。

## 5. 本地判断与内容保留

### 结构识别

1. 先识别代码围栏、缩进代码、行内代码、命令、路径、URL、数学表达式、链接目的地址等明确字面内容。
2. 保留 Markdown 标记与原始空白，按段落、列表项、表格单元格等结构建立正文候选，再做必要的句段拆分。
3. 代码块、整个目标语言段落等留在本地，直接从原文组装，不让模型携带其占位符复制整篇。
4. 翻译单位尽量保持完整语义。短句共享必要的当前段落上下文；不逐词翻译，不跨代码块粗暴拼接正文。
5. 同一句内不可分割的代码、数字和精确字面字符串仍需局部保护；保留区间不能仅因减少占位符而失去保护。

实施前用样例比较小型结构扫描器与支持 source position 的 Markdown 解析器。选择能保留原文位置的最小可靠实现；不继续堆叠一个包办所有结构的巨型正则，也不为零依赖而牺牲正确性。

### 判定规则

- 输入：纯英文保持逐字一致；明确中文自然语言需要翻译；已识别的混合英文术语保持不变。
- 输出：完整中文句段保留；中文夹少量术语不能仅因出现 ASCII 字母而触发整段重译。
- 结合周边语言、句段边界、标点、词形与代码标记区分术语和英文句子；避免单一长度阈值吞掉简短警告。
- 引号不应等同于“绝对不能翻译”：区分明确要求保留的按钮标签、字面字符串与普通引用正文；歧义样例纳入评估，优先不改精确字面内容。
- 不依赖持续增长的品牌名白名单，不用单个语言占比作为最终裁决。

### 必须覆盖的例子

| 文本/方向 | 预期 |
| --- | --- |
| 英文输入 `Inspect the files. Do NOT modify them.` | 原样提交，不调用判断或翻译模型 |
| 英文输入 `Set the label to “保存”.` | 保留精确标签，不因标签含汉字而翻译输入 |
| 中文输入 `不要运行 npm install。` | 中文指令转英文，命令逐字保留 |
| 输出 `使用 Docker 部署，使用 PyTorch 训练。` | 不为嵌入术语产生重复译文 |
| 输出 `已完成。Warning: do not retry.` | 中文保留，英文警告翻译 |
| 输出 `不要继续。Do not retry.` | 不能漏掉短英文否定句 |
| 纯代码、路径、URL、数字 | 不调用判断或翻译模型 |
| 长英文解释夹代码块与中文段落 | 只处理需要翻译的正文，代码与原中文原位保留 |

Jev 路线只共享确定性结构识别和明确无需处理的快速路径；不能先用有歧义的本地判断跳过文本，使 Jev 根本看不到候选内容。

## 6. Jev 路线

### 使用 Pi 的接口

使用 `ctx.modelRegistry.getAvailableOfType("classifier")` 列出模型，使用 `findOfType("classifier", provider, model)` 查找，再调用：

```ts
ctx.modelRegistry.classify(model, { state, questions }, { signal });
```

- 不走 `streamSimple()` 调用 Jev，不直连 TypeSafe HTTP，不添加 TypeSafe SDK 或新的 API key 配置。
- 不要求主模型启用 codemode；扩展可直接使用上述接口。
- 接口返回后检查 `stopReason`、答案 ID、类型、选项及数值有效性；不能只依赖捕获异常。
- TypeSafe 原生 `Noul` 与 Pi 的 `bool`/`probability` 并非同一字段形状；本方案优先使用 Pi 的 `choice` 类型，避免照搬 HTTP schema。

### 分类任务

- 本地先确定候选 ID 和范围；Jev 只给候选分类，不负责返回自由格式文本或字符位置。
- 问题选项为 `translate`、`keep`、`uncertain`；用英文说明目标语言、正文/术语区分和否定警告的保留要求。
- 一次调用包含多个独立问题，每个问题明确在 instructions 中指定候选 ID。官方说明模型看不到 question ID 本身，不能靠返回键名来定位材料。
- `state` 是 JSON 对象，包含方向、候选文本和必要的当前文本内部上下文。不得带入会话历史或其它外部信息。
- 分类时需要看到可读文本，而非仅看到被大量占位符遮住的语言信息；完整代码块等无需判断的内容不必发送。

### 可靠性与成本

- `confidence` 是概率分布集中程度，不是“判断正确率保证”。选项概率和置信度的使用规则需要用样例校准。
- 官方说明 Jev 以英语为主要训练语言，CJK 当前准确性较低；必须独立评估中文与混合语言，不据英文结果宣称全面提升。
- 中低置信度或 `uncertain` 回退本地；缺少/非法答案只影响对应批次或句段，不使其它有效结果失效。
- 批量提问不等于免费；控制每批文本容量、问题数、输出容量和并发。不得截断文章后把未检查部分当作已经检查。
- 分类配置、模型版本（若可获得）及使用路线可记录在扩展自身诊断中；不保存凭据，不把诊断送给主模型。
- 模型不存在、鉴权错误、超时等使用合并的可见回退提示。每次操作最多一个分类回退提示，不逐句刷屏。

## 7. 执行、恢复、超时与取消

### 局部校验与恢复

- 采用少量局部占位符或其它经样例验证的结构化映射，按片段校验；已有硬性保护不能因为减少失败提示而被取消。
- 可安全识别的传输/格式问题可规范化；不得凭相似度猜测代码、数字或标签，不将缺失字符串补在句尾。
- 局部校验失败后，在剩余预算内最多进行一次针对该片段的恢复尝试；恢复请求仅包含相关原文与规则，不发送历史。
- 不对模型明确 error/aborted/length 的半截回答当作成功，不无限重试，不自动重跑整篇或主任务。
- 多片段翻译可批量进行，但必须检测未知、重复、缺失的 ID；错误不能导致成功结果被组装到其它句段。

### 结果政策

| 情况 | 输入 | 输出 |
| --- | --- | --- |
| 无需翻译 | 原样继续 | 不增加重复译文 |
| 全部完成 | 一次性提交完整结果 | 一次性增加完整译文 |
| 个别片段恢复后仍失败 | 阻止提交，恢复原输入 | 原位保留失败片段，显示其余译文并提示局部降级 |
| 全部待翻译片段失败 | 阻止提交 | 仅保留原回答与明确失败提示，不重复贴一遍原文 |
| Jev 故障或不确定 | 提示并回退本地，然后遵守输入完整性要求 | 提示并回退本地，然后遵守输出政策 |
| 总期限耗尽 | 阻止提交，保留原文 | 可使用已完成且有效的片段，其余保留原文并说明超时 |
| 用户取消、会话替换或关闭 | 停止，保留可恢复原文，不提交 | 停止，不追加迟到的完整或部分译文 |

正常译文仍无额外标题。局部降级通过简短警告说明保留了多少片段及原因，不在正文中注入调试 ID，也不展示占位符错误堆栈。诊断要能区分输入失败、部分输出、全输出失败和分类回退。

### 预算与生命周期

- 每次输入翻译或最终回答翻译只有一个 `timeoutMs` 总期限，覆盖异步分类、分批翻译、排队等待及恢复；各子请求不能重新获得完整期限。
- Jev 有较短的内部等待上限，且不超过剩余总期限；具体值在评估后确定。
- 保留 `maxTokens` 作为请求输出上限，并为多请求总成本设置内部预算；计算累计 usage，不把输入上下文长度当作免费开销。
- 并发受限，结果按原文顺序组装。任意时候取消都要停止启动新请求并取消在途请求；provider 不响应 AbortSignal 时仍需本地终止等待。
- 仅在当前操作归属和会话 epoch 仍匹配时写入 UI/entry。中途切换路线、模型和超时不会改变旧操作。
- 正常进度仍使用原有单 spinner，必须在成功、部分成功、失败、取消和会话关闭时清理。

## 9. 风险、待校准参数与回滚

| 风险 | 控制措施 |
| --- | --- |
| 分段过细导致语义和语序受损 | 以完整句段为单位，使用当前段内上下文；先做样例对比 |
| 降低占位符数量却误改代码/数值 | 保留区间原文复制，剩余局部保护仍验证，不以静默损坏换成功率 |
| 中文夹英文短警告被当成术语 | 否定、警告与短句专项样例，不只按字符占比/词数判断 |
| Jev 对 CJK 较弱、latest 版本漂移 | 本地默认、独立评估、记录模型标识，允许选择明确版本（provider 支持时） |
| 批处理扩大失败范围或放大费用 | 明确片段映射、独立校验、有界批次/并发/恢复和统一预算 |
| 部分译文被误认为全部完成 | 明确部分降级提示；全部失败不生成重复译文 |
| 扩大菜单重新引入闪烁 | 保持单 overlay 和固定外部布局，滚动/焦点/resize 回归 |

实施选择：原文位置扫描器；完整段落优先，长段落约 1600 UTF-16 单位后在安全边界拆分；分类每批最多 8 问题 / 12000 字节；翻译请求串行；每次操作最多 64 请求 / 131072 保守预留 token；Jev 单请求上限 8 秒；选项概率至少 0.8、confidence 至少 0.5。增加 `src/request-budget.ts` 统一管理期限、取消、用量与预算。翻译每次只处理一个片段，因此不引入自由格式的批量译文 ID 映射。

这些是通过当前样例验证的初始工程界限，不是已校准的通用准确率。完整对比与已知限制见验收记录；分段可能增加请求数和成本，未宣称更快。

采用小步提交和测试先行。A 独立于 B/C；C 可通过切回本地停用；B 的回滚通过版本控制完成，不长期保留两套旧/新翻译器。配置升级前做好备份：v0.1.x 会拒绝新增字段，回退旧版本时需移除 `decisionMode`、`classifierProvider`、`classifierModel`，保留原有设置。

- [State](https://docs.typesafe.ai/concepts/state)：文本/JSON 输入，以及 CJK 准确性限制。
